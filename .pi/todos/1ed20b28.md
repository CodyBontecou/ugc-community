## Overview
Expand beyond the 3-file constraint to allow richer, more unique portfolio structures including additional HTML pages.

## Tasks
- Update the system prompt to allow additional HTML files:
  - Keep `index.html`, `styles.css`, `script.js` as required
  - Allow optional pages: `work.html`, `about.html`, `contact.html`
  - Add navigation between pages
- Update `write_file` tool validation to allow `.html` files (not just the 3 hardcoded ones)
- Update the prompt to suggest different structures based on content volume:
  - 1-3 portfolio pieces → single page with case-study sections
  - 4-8 pieces → single page with filterable grid
  - 9+ pieces → multi-page with dedicated work page
- Update storage/serving to handle additional HTML files:
  - `uploadPortfolio()` already handles any files — no changes needed
  - `portfolio-serve` route already resolves `[...path]` — no changes needed
  - Verify platform injections apply to ALL `.html` files (currently only checks extension — should work)
- Update the contact form handler injection to work on any page that has `#contact-form`

## Files
- `lib/agent/portfolio-generator.ts` (modify — update system prompt file constraints)
- `lib/agent/portfolio-prompt.ts` (modify — suggest structure based on content volume)
- Verify: `app/api/portfolio-serve/[subdomain]/[...path]/route.ts` handles multi-page
- Verify: `lib/portfolio/platform-injections.ts` works on all HTML files

## Acceptance Criteria
- Generator can create multi-page portfolios when appropriate
- Navigation between pages works correctly
- Platform injections (tracking, contact form) apply to all pages
- Existing single-page portfolios continue working unchanged
- Serving route handles sub-pages (e.g., `subdomain.ugc.community/work.html`)
