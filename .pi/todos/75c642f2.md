## Overview
The current enforcement cron (`app/api/cron/portfolio-enforcement/route.ts`) makes Vercel API calls (`addDomain`/`removeDomain`) for every creator whose status changes. With the new architecture, enforcement is just a DB flag toggle — the serving route checks `siteEnabled` and returns 404 if false.

## Tasks
- Rewrite `app/api/cron/portfolio-enforcement/route.ts`:
  - **Remove** imports: `addDomain`, `removeDomain`, `VercelApiError` from `@/lib/vercel`
  - **Remove** all `addDomain()` calls in the enable path
  - **Remove** all `removeDomain()` calls (and the 404 catch) in the disable path
  - **Keep** the posting requirement logic (monthly count check, grace period, hosting reward bypass)
  - **Keep** the email notifications (`sendPortfolioDisabledEmail`, `sendPortfolioReenabledEmail`)
  - **Keep** the DB update (`siteEnabled = true/false`)
  - The `enforceCreator()` function shrinks significantly — just DB update + email
- **Remove** `vercelProjectId` from the creator select query (no longer needed for enforcement)
- **Update** the filter: currently requires `isNotNull(users.vercelProjectId)`. Change to `isNotNull(users.subdomain)` and check that a portfolio exists in blob (or just check `siteEnabled` + `subdomain` is set)

## Impact
- Eliminates all Vercel API calls from the cron
- No more rate limit concerns for enforcement at scale
- Faster execution — DB updates are ~1ms vs Vercel API calls at ~200-500ms each
