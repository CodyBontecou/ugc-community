## Overview
Rewire the Inngest `generate-portfolio` function to upload files to Vercel Blob instead of the current GitHub → Vercel project → deploy pipeline. This is the biggest change — it replaces ~100 lines of multi-step orchestration with a single blob upload call.

## Tasks

### 5a: Update `portfolio-generator.ts`
- **Remove** the `injectTrackingAndContactForm()` function (moved to serve-time in Phase 2)
- **Remove** the call to `injectTrackingAndContactForm()` in `generatePortfolio()`
- **Keep** favicon generation and `addFaviconFiles()` — favicons are still uploaded to blob as binary files
- **Keep** the `vercel.json` file addition? **No — remove it.** No longer needed since we're not deploying to a Vercel project.
- The function should return raw creative files + favicon files only

### 5b: Rewrite `lib/inngest/functions/generate-portfolio.ts`
- **Remove** all GitHub imports and logic:
  - `createPortfolioRepo`, `pushFilesToRepo`, `repoExists`, `getRepoInfo`, `waitForRepoInitialized`
  - Octokit initialization
  - GitHub token resolution (service token, admin fallback)
  - Repo creation, existence checking, repo ID lookup
- **Remove** all Vercel project/deploy imports and logic:
  - `createProject`, `addDomain`, `linkGitHubRepo`, `createDeployment`
  - Vercel project creation, domain addition, deployment triggering
- **Replace** with blob upload:
  - Import `uploadPortfolio` from `lib/portfolio/storage.ts`
  - After Claude generates files, call `uploadPortfolio(subdomain, files)`
  - Set `siteEnabled = true` in DB
  - Set `portfolioGenerations` status to `completed`
- **Simplify steps** from 5 steps → 3 steps:
  1. `load-data` — load questionnaire + user (simplified — no GitHub token needed)
  2. `generate-with-claude` — same as today
  3. `upload-and-activate` — upload to blob, enable site in DB

### 5c: Update `load-data` step
- Remove all GitHub token resolution logic (`GITHUB_SERVICE_TOKEN`, admin fallback, `githubAccessToken`)
- Remove `githubRepoFullName`, `githubRepoId` from the user select query
- Remove `adminUserId` from event data expectations
- Only need: questionnaire data, user name, subdomain

### 5d: Update event type
- The `portfolio/generate.requested` event no longer needs:
  - `githubRepoFullName`
  - `adminUserId`
- Still needs: `generationId`, `questionnaireId`, `userId`

### 5e: Update the API route that triggers generation
- `app/api/admin/questionnaires/[id]/generate/route.ts` — remove `adminUserId` and `githubRepoFullName` from the event payload sent to Inngest
