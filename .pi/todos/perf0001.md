The October 25 audit reached a 100/100/100/100 homepage run, but repeat production runs vary with document, font, and asset delivery. Do not describe one perfect run as a guarantee of consistent scores or as a report with no recommendations. The measured runs and remaining audits are recorded in docs/performance/lighthouse-2026-10-25.json.

Completed fixes remove the broken Vercel script, isolate browser display helpers from validation/import processing, use native job disclosures, avoid unnecessary public navigation prefetches and anonymous session fetching, correct public/auth text contrast, parallelize the independent feed reads, and permit back/forward snapshots only on anonymous HTML browsing pages. Privacy, authenticated responses, RSC responses, and freshness checks retain their protections. CSS inlining uses Next's experimental inlineCss setting; review its production support when upgrading Next.

Remaining diagnostics include Next runtime code unused during initial load, legacy JavaScript in Next/Cloudflare bundles, Cloudflare's injected beacon cache lifetime, and variable server/document latency. Preserve application behavior and browser compatibility; do not suppress audits or remove useful analytics merely to hide recommendations. Measure edge/database latency before introducing any public cache, and preserve exact expiry/filter semantics and private response isolation.

Sign-in intentionally retains noindex and therefore cannot score 100 for SEO; authenticated account pages are outside the indexable public-page target. The release has seven pre-existing ESLint warnings in legacy image rendering and the Worker export, plus framework/build deprecation warnings; the audit does not claim a warning-free repository build.

Coordinate future deployments with ana00001 (consented analytics rollout). That work and its migration were not included in the isolated performance deployment. Re-run the audit after that rollout, with consent both declined and granted, and keep scripts/verify-job-posting-auth.mjs passing after every deployment.
