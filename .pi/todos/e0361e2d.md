## Overview
The actual cutover where subdomain traffic starts being served by the main app instead of individual Vercel projects. This needs to be coordinated carefully to avoid downtime.

## Pre-cutover checklist
- [ ] All existing portfolios migrated to Blob (Phase 7 complete)
- [ ] Serving route tested with at least 2-3 portfolios
- [ ] Platform injections verified (tracking pixel, contact form working)
- [ ] Enforcement cron updated (Phase 6 complete)
- [ ] Generation pipeline updated (Phase 5 complete)

## Cutover steps (execute in order)

### Step 1: Add wildcard domain to main project
- In Vercel Dashboard → `ugc-community` project → Settings → Domains
- Add `*.ugc.community` as a domain
- This tells Vercel to route ALL subdomain traffic to the main app
- **Note**: Currently individual creator Vercel projects own their specific subdomains. Adding the wildcard to the main project will take priority (Vercel routes specific domains before wildcards, but we're changing from specific→wildcard on a different project)

### Step 2: Verify serving works
- Test a few creator subdomains to confirm they're being served by the new route
- Check: HTML loads, CSS/JS load, contact form works, tracking pixel fires
- Check: Disabled sites return 404

### Step 3: Remove subdomains from individual Vercel projects
- Script or manual: for each creator's Vercel project, remove the subdomain domain
- This is now safe because the wildcard on the main project handles routing
- Can be done gradually — test one, verify, then batch the rest

### Step 4: Verify again
- All creator sites still accessible via subdomain
- No SSL issues (Vercel auto-provisions SSL for wildcard)
- Contact form submissions working
- Analytics tracking working

## Rollback plan
- If anything breaks: remove `*.ugc.community` from main project
- Individual creator Vercel projects still exist with their domains
- Traffic reverts to per-project serving immediately
