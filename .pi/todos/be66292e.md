## Overview
Create the route handler that serves portfolio files from Vercel Blob, applying platform injections at serve-time. This is the core of the new architecture — one route serves all portfolios.

## Tasks
- Create `app/api/portfolio-serve/[subdomain]/[...path]/route.ts` with a `GET` handler:
  1. Extract `subdomain` and `path` from route params
  2. Default `path` to `index.html` when empty/undefined
  3. Look up creator by subdomain in DB (cache this — see below)
  4. Return 404 if creator doesn't exist or `siteEnabled` is false
  5. Build blob URL and fetch the raw file
  6. Return 404 if blob doesn't exist
  7. Apply serve-time injections based on file type:
     - `*.html` → run through `injectPlatformCode()` from Phase 2
     - `script.js` → append `getContactFormHandler()` from Phase 2
     - Everything else (CSS, images, fonts, favicon) → pass through directly
  8. Set appropriate `Content-Type` header based on file extension
  9. Set `Cache-Control` headers:
     - HTML: `public, max-age=3600` (1 hour — allows platform updates to propagate)
     - CSS/JS: `public, max-age=86400` (1 day)
     - Images/favicons: `public, max-age=604800` (1 week)

## Performance considerations
- **DB lookup caching**: Use `unstable_cache` or a simple in-memory LRU to avoid hitting DB on every asset request for the same subdomain. One portfolio page load = ~4 requests (html, css, js, favicon). Don't want 4 DB queries.
- **Blob URL construction**: Vercel Blob URLs are deterministic when `addRandomSuffix: false` is used. Store the blob base URL or construct it from the known pattern.
- **Streaming**: Use `response.body` passthrough for binary files (images, favicons) to avoid buffering into memory.
